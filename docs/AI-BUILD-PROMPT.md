## 0. كيفية استخدام هذا الملف

**لو انت AI (Claude Code / Cursor / Copilot Workspace / أي وكيل برمجي):**
هذا الملف هو **المصدر الوحيد للحقيقة**. أي تعارض بين طلب سريع من المستخدم وبين هذا الملف — اسأل قبل ما تخالف. أي شيء غير مذكور هنا — اتبع النمط الموجود في الكود، ولو مفيش نمط، اسأل ولا تخترع.

**طريقة التشغيل الموصى بها:**
1. الصق هذا الملف كاملاً في بداية الجلسة (أو ضعه في `CLAUDE.md` / `.cursorrules`).
2. قل: `اقرأ docs/AI-BUILD-PROMPT.md ونفّذ SPRINT 0 فقط` — ثم راجع، ثم `نفّذ SPRINT 1`... إلخ.
3. لا تطلب أبداً «ابنِ المشروع كله» في أمر واحد. السبق (Sprints) في §12 مصمم بحيث كل واحد قابل للمراجعة والتشغيل.
4. بعد كل Sprint شغّل قائمة التحقق الذاتي في §13.

**بروتوكول العمل الإلزامي لك كـ AI:**
- ✅ اشتغل **Sprint واحد فقط** في المرة، وسلّم كود يشتغل فعلاً (`pnpm dev` يفتح، `pnpm test` ينجح، `pnpm build` يعدّي).
- ✅ قبل ما تكتب أي شاشة، اطبع **خطة الشاشة** (المكوّنات، الحالات، الـ API المستخدمة) واستنى الموافقة لو الشاشة كبيرة.
- ✅ لو محتاج قرار مش موجود في الملف ده — **اسأل سؤال واحد محدد** بخيارين أو تلاتة، متتوقفش وتستنى بلا داعي في باقي الشغل.
- ❌ متكتبش TODO ولا mock ولا «سأكمل لاحقاً» في كود يُسلَّم على إنه خلص.
- ❌ متسطّحش (over-simplify) الميزة عشان توفّر وقت. لو الميزة كبيرة، قسّمها وقول إنك قسّمتها.
- ❌ متضفش مكتبة جديدة من غير ما تقول ليه ومقاسها بالـ KB.

## 2. القواعد الصارمة (Hard Rules) — ممنوع كسرها

```
RULE 01  RTL أولاً. التصميم يتبني عربي/RTL كأصل، والإنجليزي/LTR هو الحالة الثانية.
         ممنوع استخدام left/right في CSS — استخدم inline-start / inline-end دايماً.

RULE 02  ميزانية الأداء مقدّسة (§10). أي PR يكسرها = يفشل. مفيش استثناءات.

RULE 03  الفلوس تتخزّن أعداد صحيحة بأصغر وحدة (قروش/هللات) — نوع BigInt/Int.
         ممنوع Float للمبالغ نهائياً. العرض بس هو اللي بيقسم على 100.

RULE 04  كل جدول فيه tenant_id + سياسة RLS في قاعدة البيانات نفسها.
         الاعتماد على شرط في كود التطبيق لوحده = ثغرة أمنية.

RULE 05  رقم الهاتف بصيغة E.164 دايماً (+201012345678) وهو مفتاح هوية العميل الأساسي.

RULE 06  كل الأوقات UTC في قاعدة البيانات. التحويل للتوقيت المحلي في طبقة العرض فقط.

RULE 07  كل عملية كتابة خارجية (شحنة/دفعة/رسالة) لازم Idempotency-Key.
         التكرار ممنوع ينتج شحنتين.

RULE 08  ممنوع أي طلب شبكة لطرف ثالث قبل تفاعل المستخدم في صفحات المتجر.
         البيكسلات والشات والتحليلات كلها مؤجّلة.

RULE 09  ممنوع شاشة بيضاء. كل حالة لها تصميم: تحميل / فاضي / خطأ / بدون إنترنت / بدون صلاحية.

RULE 10  كل النصوص في ملفات ترجمة (i18n). ممنوع نص عربي أو إنجليزي مكتوب داخل مكوّن.

RULE 11  الأرقام المالية والكميات تُعرض بأرقام لاتينية (1,234) مع خط جدولي (tabular-nums)
         حتى في الواجهة العربية — ده الأوضح للتاجر والأسهل في المسح البصري.

RULE 12  كل إجراء خطير (حذف، تصدير عملاء، تغيير حساب التحويل) لازم تأكيد + سجل تدقيق.

RULE 13  الوصولية WCAG 2.2 AA: تباين ≥ 4.5:1 للنص، كل زر له اسم، التنقل بالكيبورد كامل،
         focus ring واضح، مساحة لمس ≥ 44×44px.

RULE 14  ممنوع تثبيت مكتبة UI جاهزة ثقيلة (MUI / AntD / Chakra). نبني على
         Tailwind + Radix primitives فقط.

RULE 15  ممنوع «سأكمل لاحقاً». الكود المُسلَّم يشتغل ومُختبَر.
```

## 5.1 الحمض النووي للتصميم (Design DNA)

**الإحساس المطلوب:** «أداة محترف سريعة» — مش «موقع شركة ناشئة جميل».
الإلهام: كثافة معلومات **Linear** + وضوح **Shopify Polaris** + سرعة **Vercel** + دفء عربي في اللغة والخط.

### القوانين الجمالية الخمسة

```
① الكثافة المحترمة (Respectful Density)
   التاجر بيشوف 200 أوردر في اليوم. مش عايز مساحات بيضا شاعرية.
   صف الجدول ارتفاعه 48px مش 72px. لكن التنفّس بين الأقسام موجود.

② اللون له وظيفة، مش زينة
   اللون الأساسي (Teal) للأفعال الأساسية فقط. الحالات لها ألوان ثابتة.
   الشاشة الافتراضية = رمادي محايد + أبيض. أي لون زيادة = ضوضاء.

③ التسلسل البصري بالحجم والوزن، مش بالخطوط والصناديق
   قلّل الحدود (borders). استخدم المسافة والوزن الخطي لفصل المحتوى.
   ظل خفيف جداً أو حد 1px بلون slate-200 — مش صناديق مزدوجة.

④ الحركة تشرح، متبهرش
   150–200ms، easing طبيعي. الحركة تقول «الحاجة دي جت من هنا».
   ممنوع أي أنيميشن أطول من 300ms في لوحة التحكم.

⑤ الرقم هو البطل
   في شاشات التاجر، الرقم أكبر عنصر. العنوان تحته صغير ورمادي.
   ومعاه دايماً مقارنة (+12% عن أمس) — الرقم لوحده بلا سياق عديم القيمة.
```

**قواعد الطباعة العربية (مهمة جداً):**
- ارتفاع السطر في العربي لازم **أعلى 10%** من اللاتيني عشان التشكيل والنقط.
- ممنوع `text-transform: uppercase` على العربي (بلا معنى) وممنوع `letter-spacing` سالب.
- الأرقام: `font-variant-numeric: tabular-nums` في كل الجداول والمبالغ.
- العرض الأقصى لفقرة نصية: `65ch`.
- **العملة تُكتب بعد الرقم:** `1,250.00 ج.م` — والرقم بخط `600` والعملة بـ `400` ولون `text-secondary`.

```css
--duration-instant: 100ms;  /* hover, focus */
--duration-fast:    150ms;  /* dropdowns, tooltips, badges */
--duration-normal:  200ms;  /* modals, drawers, tabs */
--duration-slow:    300ms;  /* page-level transitions فقط */
--ease-out:    cubic-bezier(0.16, 1, 0.3, 1);      /* الدخول */
--ease-in-out: cubic-bezier(0.65, 0, 0.35, 1);     /* التنقل */
```
**قواعد:**
- الدخول `ease-out` + إزاحة 4–8px. الخروج أسرع بـ 50ms.
- `@media (prefers-reduced-motion: reduce)` → عطّل كل الإزاحات، خلّي التلاشي فقط.
- **في RTL:** الـ Drawer يدخل من **اليمين**، والقوائم تنفتح لليمين. استخدم منطق `inline-start/end` مش `translateX` ثابت.
- ممنوع أي skeleton يلمع (shimmer) أسرع من 1.5s — بيسبب إجهاد بصري.

### الأيقونات
Lucide، حجم `16px` داخل النص و`20px` للأزرار و`24px` للتنقل. سمك الخط `1.5`. **الأيقونة لوحدها ممنوعة كزر** إلا مع `aria-label` + tooltip.

## 5.3 قواعد RTL — إلزامية

```css
/* ✅ صح */
margin-inline-start: 12px;   padding-inline-end: 16px;
border-inline-start: 2px;    inset-inline-start: 0;
text-align: start;

/* ❌ غلط */
margin-left: 12px;  padding-right: 16px;  left: 0;  text-align: right;
```

| العنصر | السلوك في RTL |
|---|---|
| الشريط الجانبي | يمين الشاشة |
| فتات الخبز (Breadcrumb) | يقرأ يمين← يسار، الفاصل `‹` مش `›` |
| أسهم «التالي/السابق» | تنعكس اتجاهياً |
| شريط التقدّم | يمتلئ من اليمين |
| الجداول | العمود الأول (الأهم) على اليمين، والإجراءات على اليسار |
| الرسوم البيانية | **محور الزمن يفضل يسار←يمين** (لا ينعكس — ده العرف العالمي للبيانات)، لكن التسميات واللِجند RTL |
| الأرقام والأكواد و AWB و SKU | تُعرض LTR داخل حاوية `dir="ltr"` مع محاذاة `start` |
| رقم الهاتف | LTR دايماً: `+20 101 234 5678` |
| المدخلات (inputs) | النص عربي RTL، لكن حقل الهاتف/البريد/الرابط `dir="ltr"` |

## 6.1 ⭐ الأوردرات (Orders List) — الشاشة رقم 1 في المنتج

**الهدف:** التاجر يفتحها 30 مرة في اليوم. لازم تجاوب في أقل من 300ms وتديله السيطرة على 500 أوردر من غير ما يتوه.

**سلوكيات إلزامية:**
1. **صف واحد = سطرين:** الأساسي (رقم/عميل/مبلغ/حالة) + سطر رمادي صغير (الهاتف/الوقت النسبي/المصدر).
2. **الوقت النسبي** بجانب الأوردرات الجديدة: `⏱ من دقيقتين` — وأي أوردر أقل من 10 دقايق له خلفية `brand-50` خفيفة.
3. **مؤشر المخاطرة** ⚠️ بجانب العميل لو الدرجة > 50، مع tooltip يشرح ليه.
4. **الضغط على الصف** → يفتح **Drawer** من الجنب (مش صفحة جديدة) للتفاصيل السريعة. الضغط على رقم الأوردر → صفحة كاملة.
5. **التحديث الحيّ:** أوردر جديد يظهر فوق بأنيميشن دخول خفيف + عدّاد في التبويب + صوت اختياري (إعداد).
6. **الإجراءات الجماعية** لغاية 5,000 أوردر → تشتغل في الخلفية مع شريط تقدّم وإشعار عند الانتهاء.
7. **اختصارات:** `j/k` تنقّل بين الصفوف، `Enter` يفتح، `c` يأكّد، `p` يطبع بوليصة، `/` يركّز البحث.
8. **الفلاتر تتحفظ في الـ URL** — الرابط قابل للمشاركة مع الفريق.

**معايير القبول:**
- `AC-1` تحميل أول 50 أوردر في ≤ 300ms (p95) مع 100 ألف أوردر في القاعدة.
- `AC-2` التمرير في 10,000 صف بـ 60fps.
- `AC-3` في الموبايل: بطاقات، وكل بطاقة فيها زر أساسي واحد (أكّد / اطبع بوليصة حسب الحالة).
- `AC-4` تحديد «كل النتائج» (مش الصفحة) بيشتغل على الفلتر الحالي مش على المحمّل بس.

## 6.3 ⭐⭐ مركز التأكيد (Confirmation Desk) — الميزة القاتلة

**الهدف:** موظف يخلّص 100 أوردر في الساعة بدون ما يشيل إيده من الكيبورد. **شاشة واحدة، أوردر واحد، قرار واحد.**

```
┌───────────────────────────────────────────────────────────────────────┐
│ مركز التأكيد        متبقي 47 أوردر   ●●●○○ إنتاجيتك: 68 أوردر/ساعة   │

│  │ أحمد محمد                              │ │  #1043  الجيزة  850     │
│  │ +20 101 234 5678        [📞 اتصل]     │ │  #1044  القاهرة 1,200   │
│  │ الجيزة — الدقي — 12 ش التحرير          │ │  #1045  الإسكندرية 430  │
│  │                                        │ │  ...                    │
│  │ شنطة جلد بني × 2 ......... 800.00 ج.م │ │                          │
│  │ الشحن ....................  50.00 ج.م │ │  ⚙️ ترتيب: الأقدم ▾      │
│  │ الإجمالي COD ............. 850.00 ج.م │ │                          │
│  └────────────────────────────────────────┘ │                          │
│                                             │                          │
│  📊 تاريخ العميل: 5 أوردرات · رفض 1 مرة    │                          │
│  🤖 السبب في المخاطرة: رفض سابق، عنوان ناقص│                          │
│                                             │                          │
│  ┌─────────────┬──────────────┬───────────┐ │                          │
│  │ ✓ أكّد  [1] │ ✕ ألغِ   [2] │ ⏰ أجّل[3]│ │                          │
│  └─────────────┴──────────────┴───────────┘ │                          │
│  💬 ابعت واتساب [W]   📝 عدّل الأوردر [E]  │                          │
└─────────────────────────────────────────────┴──────────────────────────┘
```

**سلوكيات إلزامية:**
1. **التنقّل بالكيبورد بالكامل:** `1` أكّد → يقفز للأوردر اللي بعده فوراً. `2` يفتح أسباب الإلغاء (اختيار برقم كمان). `3` يأجّل بمواعيد جاهزة (بعد ساعة / بكرة الصبح / بعد يومين).
2. **prefetch للأوردر اللي بعده** — الانتقال لازم يكون **فوري (0ms محسوس)**.
3. **أسباب الإلغاء مُهيكلة** (قائمة ثابتة + ملاحظة اختيارية): مرد مايرد · غيّر رأيه · السعر غالي · طلب بالغلط · مش هيكون موجود · العنوان غلط · أوردر مكرر.
4. **زر واتساب** يبعت قالب معتمد بضغطة، والرد بيحدّث الحالة تلقائياً.
5. **عدّاد إنتاجية** للموظف في الأعلى — تحفيز خفيف مش مراقبة عدائية.
6. **منع التصادم:** أوردر بيتفتح من موظف بيتقفل عن الباقين (lock مع timeout 3 دقايق).
7. **تراجع:** آخر إجراء قابل للتراجع خلال 10 ثواني من Toast.
8. لو `RiskScore > 70` → المنصة تقترح تلقائياً: «اطلب OTP» أو «اطلب دفعة مقدمة» كأزرار إضافية.

**معايير القبول:**
- `AC-1` الانتقال بين أوردرين ≤ 100ms.
- `AC-2` موظف يقدر يخلّص 30 أوردر من غير ما يمس الماوس.
- `AC-3` كل قرار يتسجّل في `ConfirmationAttempt` مع الموظف والقناة والسبب والوقت.

## 6.8 ⭐⭐ شيك أوت المتجر (Storefront Checkout) — أثمن 25 ثانية

**قاعدة حاكمة:** كل عنصر مش بيقرّب المستخدم من إتمام الأوردر → **احذفه**.

```
موبايل (الأساس — 90% من الترافيك):

│ ─────────────────────────   │
│ الإجمالي        850.00 ج.م  │
├─────────────────────────────┤
│ ┃   أكّد الأوردر           ┃ │ ← زر عريض 52px، لزج في الأسفل
├─────────────────────────────┤

│    خلال 14 يوم · ⭐ 4.8     │
```

**قواعد إلزامية:**
1. **4 حقول بس** في مسار COD. أي حقل زيادة لازم يتبرر بزيادة تحويل مقاسة.
2. **ممنوع إجبار تسجيل حساب.** الشراء كضيف هو الافتراضي.
3. **لا انتقال صفحات.** كل حاجة في صفحة واحدة.
4. **حفظ لحظي:** كل حرف بيتكتب يتحفظ (سلة متروكة قابلة للاسترداد) — بدون أي تأخير محسوس.
5. **التحقق بعد الخروج من الحقل (blur)** مش أثناء الكتابة — التحقق أثناء الكتابة مزعج.
6. **الملء المسبق:** لو الرقم اشترى قبل كده من نفس المتجر → املا العنوان تلقائياً واعرض «ده عنوانك السابق، صح؟».
7. **الشحن يتحدّث بعد اختيار المحافظة** بدون إعادة تحميل، مع انتقال ناعم للرقم.
8. **زر التأكيد لزج** في أسفل الشاشة على الموبايل، وفيه المبلغ: «أكّد الأوردر · 850 ج.م».
9. **بعد الضغط:** الزر يقفل فوراً + «بنسجّل أوردرك...» + منع الضغط المزدوج (idempotency).
10. **صفحة الشكر** فيها: رقم الأوردر، متى يوصل، زر واتساب للتواصل، وزر «تابع الشحنة». وتشغّل حدث الشراء (browser + server CAPI بنفس `event_id`).
11. **ممنوع:** كوبونات ظاهرة كحقل كبير (بتخلي الناس تسيب الصفحة تدوّر على كوبون) — خليه رابط صغير «عندك كوبون؟».
12. **الأداء:** الشيك أوت لازم يشتغل **بدون JS** كحد أدنى (progressive enhancement). LCP ≤ 1.0s.

**معيار قبول نهائي:** `وسيط زمن إتمام الأوردر من فتح الشيك أوت للتأكيد ≤ 25 ثانية على موبايل متوسط وشبكة 3G.`

```
✓ استرجاع خلال 14 يوم
─────────────────
┃  اشتري دلوقتي  ┃  ← يودّي للشيك أوت مباشرة (تخطي السلة)

─────────────────
الوصف (مطوي بعد 3 سطور)

```

**قواعد:**
- **تبديل النوع (variant) فوري بلا أي طلب شبكة** — كل الأنواع محمّلة مسبقاً في الـ HTML.
- الصور بأبعاد ثابتة (`width`/`height`) لمنع أي CLS.
- «اشتري دلوقتي» هو الزر الأساسي في أسواق COD — مش «ضيف للسلة».
- شريط لزج يظهر عند التمرير فيه (السعر + اشتري دلوقتي).
- ممنوع popup يغطي الشاشة قبل ما المستخدم يتفاعل.

# 🔌 القسم 8 — طبقة التكاملات (Connectors)

**المبدأ:** كل شريك بينفّذ نفس الواجهة. الموصّل الجديد لازم يتبني في **يوم واحد** بلا تعديل في النواة.

```ts
// packages/connectors/contracts/shipping.ts
export interface ShippingConnector {
  readonly code: string;                    // 'bosta'
  readonly name: { ar: string; en: string };
  readonly countries: string[];             // ['EG']
  readonly capabilities: {
    cod: boolean; pickup: boolean; returns: boolean;
    labelFormats: ('pdf' | 'zpl')[]; codStatement: boolean;
  };

  getRates(i: RateInput): Promise<Rate[]>;
  createShipment(i: ShipmentInput, idempotencyKey: string): Promise<ShipmentResult>;
  getLabel(awb: string, format: 'pdf' | 'zpl'): Promise<Buffer>;
  track(awb: string): Promise<TrackingUpdate[]>;
  cancel(awb: string): Promise<void>;
  schedulePickup(i: PickupInput): Promise<PickupResult>;
  createReturn(awb: string): Promise<ShipmentResult>;
  fetchCodStatement(from: Date, to: Date): Promise<SettlementLine[]>;

  /** ⭐ إلزامي: تحويل حالة الناقل الخام للقاموس الداخلي */
  normalizeStatus(raw: string): ShipmentStatus;
  verifyWebhook(headers: Headers, body: string): boolean;
}
```

**قواعد كل موصّل — ممنوع تسليم موصّل بدونها:**
```
① Idempotency: نفس المفتاح = نفس النتيجة، ممنوع شحنة مكررة
② Retry: تراجع أسّي (1s, 2s, 4s, 8s...) + jitter، حتى 24 ساعة، ثم DLQ ظاهر للتاجر
③ Circuit breaker: 5 أخطاء متتالية = وقف الموصّل 60 ثانية والتحويل للبديل
④ Timeout: 10 ثواني لأي استدعاء، ولو أطول → للطابور
⑤ Normalization: أي حالة مش معروفة تتسجّل في طابور «حالات غير مطبّعة» ومتتجاهلش
⑥ Contract tests: مجموعة اختبارات تشتغل يومياً على sandbox الشريك
⑦ Logging: correlation_id واحد من الواجهة للشريك. ممنوع تسجيل بيانات حسّاسة.
⑧ Config schema: كل موصّل يعرّف حقول إعداده بـ Zod عشان الـ UI يتولّد تلقائياً
```

**الحالات الداخلية الموحّدة (متزوّدش عليها بدون قرار):**
```ts
type ShipmentStatus =
  | 'created' | 'picked_up' | 'in_transit' | 'out_for_delivery'
  | 'delivered' | 'failed_attempt' | 'returned_to_origin'
  | 'lost' | 'cancelled';
```

**نفس النمط للمدفوعات والمراسلة:**

```
⑨ كل السكربتات الخارجية (بيكسل/شات/تحليلات) بعد التفاعل الأول أو في Web Worker.
⑩ تكيّف مع الشبكة: navigator.connection.effectiveType == '2g' → صور أخف وتأجيل أكتر.
⑪ قاعدة البيانات: فهارس مطابقة لأنماط الاستعلام، cursor pagination (ممنوع OFFSET

⑫ العمليات البطيئة (شحنة/رسالة/مزامنة) في طابور + تحديث تفاؤلي في الواجهة.
⑬ RUM: اجمع Core Web Vitals من متاجر حقيقية، واعرض للتاجر:
```
